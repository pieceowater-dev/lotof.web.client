# Матрица доступов: персональные данные, экспорт, чувствительные действия

Проверено по коду шлюзов (2026-10). Роль берётся из токена приложения; проверки стоят в шлюзе, поэтому обойти их из браузера нельзя.

| Приложение | Кто НЕ видит ПДн клиента | Что скрывается | Где реализовано |
|---|---|---|---|
| Menu | COOK (повар) | имя, телефон, адрес, привязка к клиенту | `order.roles.go` → `maskedOrder`, единственный путь отдачи заказа |
| Issues | VIEWER | имя, телефон, адрес, привязка к клиенту | `task.pii.go` → `maskedTask` |
| Plans | MASTER (мастер) | телефон клиента в записи (имя остаётся) | `booking.pii.go` → `maskedBooking` |
| Contacts | VIEWER (чтение) | телефоны и почта в списках и карточках | `helpers.go`, `AccessRoleContextKey` |
| Goods | покупателей как персональных данных не хранит | — | роли ограничивают операции |

## Экспорт

| Что | Кто может | Где проверяется |
|---|---|---|
| Клиенты Contacts в Excel | OWNER, ADMIN (право `contacts.client.export`) | кнопка по `contactsCan`; данные и так проходят маску |
| Заказы Menu в Excel | OWNER, MANAGER | кнопка в интерфейсе; строки уже замаскированы по роли |
| Отчёт по исполнителям Menu | OWNER, MANAGER | `@menuAuth` на `executorReport` |
| Ежедневный отчёт Issues | OWNER, MANAGER | `@issuesAuth` на `boardDailyReport` |
| Операции Goods (склад, касса) | по ролям: касса — CASHIER+, склад — STOCKKEEPER+, управление — OWNER/MANAGER | `@goodsAuth(roles: …)` на каждом поле |

## Чувствительные действия с повторным входом через Google

Требуют входа не старше 5 минут (`@freshAuth`, код `REAUTH_REQUIRED`, в веб — окно «Подтвердите вход»):
- настройки телефонии, сохранение и удаление интеграции (Contacts).

## Хранилище файлов

- Загрузка в Contacts: роль не ниже editor; ссылки на файлы подписываются и привязаны к пространству имён.
- Лимит места на приложение задаётся в тарифе (`storage_mb`), загрузка сверх лимита отклоняется.

## Итог аудита

Обходных путей отдачи заказа/задачи мимо маски не найдено (Menu: `mapOrder` вызывается только из `maskedOrder`). Расхождений между кнопкой в интерфейсе и проверкой в шлюзе нет, кроме экспорта заказов Menu: он собирается в браузере из уже загруженных строк, так что запретить его можно только ролью на чтение (она и так маскирует данные).
