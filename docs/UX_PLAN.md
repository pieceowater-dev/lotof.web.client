# UX-план по сервисам (без Atrace)

Основа: просмотр экранов lota в браузере на телефоне (390 px), планшете (820 px) и ноутбуке (1440 px), замечания владельца, сравнение с конкурентом (`COMPETITOR_COMPARISON.md`). Для каждого сервиса: кто пользуется, главные сценарии, где трение, что сделано в этом заходе, что остаётся.

## Сквозные принципы

1. **Телефон — полноценный клиент.** Таблица шире экрана превращается в карточки; главное действие (создать, оплатить, принять) доступно без прокрутки вбок.
2. **Один главный способ.** Одно заметное действие на экране; остальные — вторичные кнопки или меню. Не ставить кнопки «посреди» чужих рядов (кнопка «Сохранить фильтр» стояла между плитками статусов).
3. **Состояния видны.** Пусто, загрузка, ошибка — каждое со своим текстом и действием («Повторить»), а не серая коробка или голый тост «Ошибка».
4. **Язык человека.** Никаких сырых значений (`VACATION`, коды, пути). Подписи и даты на языке интерфейса.
5. **Не терять ввод.** Окно в окне не должно закрывать родителя; черновик живёт, пока человек не отменил.
6. **Одинаковые детали везде.** Фильтры — капсулы (`pill-filter`) с градиентом активного; кнопки — `at-btn`; плитки итогов — `at-stat`; шапка страницы: заголовок, подпись, действия справа.
7. **Подвал не мешает.** Содержимое на телефоне заканчивается, и только потом идёт подвал.

## Заказы (Menu)

**Кто:** менеджер приёмки (быстро завести заказ и найти старый), исполнитель (мои заказы на телефоне), владелец (отчёты, настройки), клиент (витрина, отслеживание).

**Главные сценарии:** принять заказ → назвать цену → согласовать → выполнить → принять оплату → выдать; найти заказ; посмотреть, что горит (срочные, просроченные, «связаться»).

| Трение | Решение | Статус |
|---|---|---|
| Кнопка «Сохранить фильтр» стояла в ряду плиток статусов, выглядела чужой | перенесена в строку фильтров, компактная | сделано |
| Фильтр по типу заказа — другой вид, чем остальные | капсулы `pill-filter` | сделано |
| Кнопка «Ещё фильтры» на телефоне — пустая полоса с иконкой | подпись всегда видна | сделано |
| Список на телефоне уходил под подвал | подвал после содержимого | сделано |
| Комментарий/фото к заказу нельзя было оставить прямо в ленте | композер в таймлайне: текст, фото, файлы, вставка и перетаскивание | сделано |
| Страница отчётов: один заголовок на все вкладки, ручное «Обновить», пустая серая коробка | заголовок по вкладке, периоды одним нажатием, автообновление, плитки, полоски, пустые состояния, Excel | сделано |
| Клиент не мог согласовать цену сам | кнопка «Согласен с ценой» на странице отслеживания | сделано |
| Заказ приходится двигать вручную после согласования цены | статус может «забирать» заказ по отметке цены | сделано |
| Документы: длинный список шаблонов в меню печати | группы по категориям | сделано |
| Открытая карточка заказа не знала, что клиент согласовал цену | уведомление «Заказ изменён — Обновить» (не мешает собственным действиям) | сделано |
| Остаток детали не виден при выборе позиции | плашка «В наличии: N» / «Нет в наличии» у позиций с рецептом склада | сделано |

## Задачи и доставка (Issues)

**Кто:** диспетчер (раздаёт и следит), курьер/мастер (телефон, Zen-режим), менеджер (воронка).

| Трение | Решение | Статус |
|---|---|---|
| Не хватало быстрых представлений («срочные», «новые за неделю») | капсулы над доской | сделано |
| Доставка: непонятно, что принять от клиента и сколько платить курьеру | поля в карточке, «мастер сам / курьер» | сделано |
| Курьер не мог вернуть задачу | «Отказаться» с причиной, прежний исполнитель запоминается | сделано |
| Несколько исполнителей: отметка «сделал» без пояснения | запрос «что сделано?» → комментарий в задаче | сделано |
| Лид из воронки нельзя превратить в заказ | кнопка «Создать заказ» открывает форму заказа с данными клиента | сделано |
| Настройки доски — длинный список переключателей без группировки | два раздела: «Ход выполнения» и «Доставка и выезд» | сделано |
| Карта и список логистики на разных страницах | общий экран «список слева, карта справа» | в бэклоге |

## Как проверять UX дальше

- Каждый экран — на трёх ширинах (390, 820, 1440), светлая и тёмная тема, русский/английский/казахский.
- Автоскан горизонтального переполнения (`scrollWidth > clientWidth`) на всех маршрутах — в этом заходе по ключевым экранам Menu, Goods, Issues, Contacts переполнений не найдено.
- Реальные сценарии «сквозь» (создать заказ → цена → оплата → выдача) раз в релиз.
